# Database Design

PostgreSQL 16 + pgvector. Migrations: `services/api/migrations` (goose). Status of each table is tracked in IMPLEMENTATION_TRACKER.md; tables are introduced by the phase that needs them.

## 1. Conventions

- Primary keys: `uuid` (generated by the application as UUIDv7, so IDs are time-ordered and index-friendly).
- Every user-owned table has `user_id uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE` and an index leading with `user_id`. **All queries filter by `user_id`.**
- Timestamps: `created_at timestamptz NOT NULL DEFAULT now()`, `updated_at` where rows are mutable.
- Enumerations: `text` + `CHECK` constraints. They are easier to migrate than PG enums.
- Soft delete: not used by default. Account deletion is a hard cascade, plus scrubbing of object storage.
- Secrets (OAuth tokens) are encrypted with AES-256-GCM in the application, key from `DATA_ENCRYPTION_KEY`, stored as `bytea` with a key version.
- Provenance on professional facts: `source` ∈ {`USER_ENTERED`,`CV_IMPORT`,`AI_INFERRED`} and `verification` ∈ {`VERIFIED`,`UNVERIFIED`,`REJECTED`}.

## 2. Entity overview by module

### Identity (Phase 2)
| Table | Key columns / constraints |
|---|---|
| `users` | `email citext UNIQUE`, `password_hash`, `display_name`, `status` (`ACTIVE`,`DISABLED`,`PENDING_DELETION`), `email_verified_at` |
| `user_sessions` | `token_hash bytea UNIQUE`, `csrf_token_hash`, `expires_at`, `idle_expires_at`, `ip`, `user_agent`, `revoked_at` |
| `password_reset_tokens` | `token_hash UNIQUE`, `expires_at`, `used_at` |
| `idempotency_keys` | `(user_id, key) UNIQUE`, `request_hash`, `response_status`, `response_body`, `expires_at` |

### Profile (Phase 2)
| Table | Notes |
|---|---|
| `professional_profiles` | 1:1 with user: headline, summary, location_country (ISO-3166), city, years_experience, links (jsonb), completeness cache |
| `work_experiences` | employer, title, start/end (date, nullable end = current), description, achievements (jsonb), `source`, `verification` |
| `education_records` | institution, degree, field, dates, provenance |
| `skills` | canonical skill catalogue: `slug UNIQUE`, `name`, `category`, `aliases text[]` |
| `profile_skills` | `(user_id, skill_id) UNIQUE`, level, years, evidence refs, provenance |
| `certifications`, `projects` | provenance on each |
| `user_preferences` | roles[], industries[], employment_types[], locations[], remote_mode (`REMOTE_ONLY`,`HYBRID_OK`,`ONSITE_OK`), min_salary + currency + period, needs_sponsorship, willing_to_relocate, notice_period_days, eligible_countries[] (where the user can legally work) |
| `profile_documents` | storage_key, original_filename, mime, size, sha256, kind (`CV`,`COVER_LETTER`,`EVIDENCE`,`GENERATED_CV`), parse_status |
| `document_versions` | `(document_id, version) UNIQUE`, content (jsonb structured), storage_key for rendered file, created_by (`USER`,`AGENT`), approval state |
| `profile_extractions` | proposal from a CV parse: payload jsonb, status (`PENDING_REVIEW`,`APPLIED`,`DISCARDED`), model/prompt version |

### Jobs (Phase 3)
| Table | Notes |
|---|---|
| `job_sources` | `kind` (`GREENHOUSE`,`LEVER`,`ASHBY`,`REMOTIVE`,`REMOTEOK`), `identifier` (board token), `enabled`, `rate_limit_per_min`, health fields (`last_success_at`, `consecutive_failures`) |
| `jobs` | global (not user-owned). `(source_id, external_id) UNIQUE`, `canonical_url`, `apply_url`, `apply_email`, title, company_name, description_html (sanitised), description_text, location_raw, remote_status (`REMOTE`,`HYBRID`,`ONSITE`,`UNKNOWN`), eligible_countries[] (nullable = unknown), sponsorship (`YES`,`NO`,`UNKNOWN`), salary_min/max/currency/period (nullable), seniority, employment_type, posted_at, closes_at, first_seen_at, last_seen_at, expired_at, `content_hash`, `dedupe_key` (normalised company + title + location), `extraction` jsonb + version |
| `job_skills` | `(job_id, skill_id, requirement)`, requirement ∈ {`REQUIRED`,`PREFERRED`} |
| `job_embeddings` | `job_id PK`, `embedding vector(N)`, model, HNSW index |
| `saved_searches` | user-owned filters jsonb |
| `discovery_runs` | per source run: counts (fetched/new/updated/expired/errors), started/finished, error summary |

### Matching (Phase 4)
| Table | Notes |
|---|---|
| `job_match_results` | `(user_id, job_id, algorithm_version) UNIQUE`, overall_score numeric(5,2), dimension scores, eligibility (`ELIGIBLE`,`INELIGIBLE`,`UNKNOWN`), blockers jsonb, missing_skills jsonb, signals jsonb, confidence, explanation, weights jsonb, profile_hash, job_hash |
| `match_feedback` | user thumbs/reason per result |

### Applications (Phases 5–6)
| Table | Notes |
|---|---|
| `applications` | `(user_id, job_id) UNIQUE` (one application per job per user), status, channel (`ASSISTED`,`EMAIL`), idempotency_key, notes |
| `application_status_history` | from/to status, actor (`USER`,`AGENT`,`SYSTEM`), reason, at |
| `application_documents` | link to document_versions with role (`CV`,`COVER_LETTER`) |
| `application_answers` | question, answer, source facts refs, status (`DRAFT`,`NEEDS_USER`,`APPROVED`) |
| `submission_attempts` | channel, status (`PENDING`,`SUCCEEDED`,`FAILED`), error, idempotency_key UNIQUE |
| `submission_evidence` | type (`USER_ATTESTED`,`EMAIL_SENT`,`EMAIL_CONFIRMATION`,`ATS_CONFIRMATION`), reference (message id / URL), attachment document id |

### Outreach (Phase 7)
`recruiter_contacts` (with `email_verification`: `UNVERIFIED`,`USER_PROVIDED`,`PROVIDER_VERIFIED`,`BOUNCED`), `email_accounts` (encrypted tokens, scopes, status), `outreach_messages` (draft/approved/sent/failed, gmail message/thread ids, `UNIQUE(idempotency_key)`), `follow_ups` (due_at, status, cancelled_reason), `contact_preferences` (do-not-contact).

### Automation & workflows (Phase 8)
| Table | Notes |
|---|---|
| `automation_settings` | per user: mode (`DISCOVERY_ONLY`,`HUMAN_APPROVED`,`CONTROLLED_AUTONOMOUS`), `paused` (global kill switch), limits jsonb |
| `automation_permissions` | per action type (`SEND_OUTREACH_EMAIL`, `SEND_APPLICATION_EMAIL`, `PREPARE_DOCUMENTS`…): granted, constraints jsonb, `revoked_at` |
| `search_goals` | objective text, structured constraints jsonb, schedule (cron), status |
| `workflow_executions` | goal_id, type, status (`PENDING`,`RUNNING`,`NEEDS_INPUT`,`AWAITING_APPROVAL`,`PAUSED`,`SUCCEEDED`,`PARTIALLY_SUCCEEDED`,`FAILED`,`CANCELLED`), plan jsonb, plan_version |
| `workflow_tasks` | workflow_id, type, agent, input/expected_output/result jsonb, status, attempts, max_attempts, timeout_s, depends_on uuid[], required_permissions text[], started/completed_at, error |
| `approval_requests` | subject type/id, action, payload snapshot, status (`PENDING`,`APPROVED`,`REJECTED`,`EXPIRED`), decided_at |
| `agent_runs`, `agent_tool_calls` | per task: agent, tool, args (redacted), result summary, latency, model, prompt_version, token usage |

### Platform
`notifications`, `audit_events` (append-only: actor, action, subject, outcome, metadata; no UPDATE/DELETE grants for the app role in production), `prompt_versions`, `model_versions`, `usage_records` (tokens, cost, per user per day → budgets and billing readiness), and River's own tables (`river_job` etc., created by River migrations).

## 3. Key indexes
- `jobs`: `(dedupe_key)`, `(expired_at) WHERE expired_at IS NULL`, GIN on `to_tsvector(title || description_text)`, `(posted_at DESC)`.
- `job_match_results`: `(user_id, overall_score DESC)`.
- `applications`: `(user_id, status)`.
- `workflow_tasks`: `(workflow_id, status)`.
- `audit_events`: `(user_id, created_at DESC)`.

## 4. Retention (initial proposal — needs legal review)
| Data | Retention |
|---|---|
| Sessions | expire per policy; purge 30 days after expiry |
| Password reset tokens | purge after 24 h |
| Expired jobs | keep 180 days (analytics), then delete description text |
| Audit events | 2 years |
| Uploaded CVs / generated docs | until user deletes, or account deletion |
| Raw email bodies | not stored; only metadata + the snippet needed for reply association |
